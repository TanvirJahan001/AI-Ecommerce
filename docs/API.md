# Application and Integration Contracts

**Purpose:** authoritative current store transport and integration boundary. **Status:** current local implementation contract; real-provider and commercial release gates remain open. **Updated:** 2026-11-14. **Related:** [DATA](DATA.md) · [USERS](USERS.md) · [SECURITY](SECURITY.md) · [Architecture](Architecture.md) · [DELIVERY](DELIVERY.md)

## Current transport and shared rules

`GET /api/store?resource=...` and `POST /api/store` with JSON `{action,...}` implement commerce. `/api/auth/*` is Better Auth; `/api/auth/identity` returns minimal current identity; `/api/health` checks PostgreSQL; `/api/admin/export` is owner-only CSV. The earlier resource-specific REST routes were proposals superseded by this transport; they are not implemented endpoints. Exact field schemas are in [route](../src/app/api/store/route.ts), domain effects in DATA.

JSON is UTF-8. All API `*_minor` amounts are integer BDT poisha; UI BDT decimal strings pass through the exact parser before submission. Server validation and recalculation remain authoritative. No caller-supplied price, delivery charge, verified-payment flag or role is trusted. Errors contain code/message and status, with field validation where applicable; UI maps access codes to friendly messages. Cookie mutations require APP_ORIGIN. Sensitive responses are private/no-store.

Owner detail uses a short transaction and order lock; authorization precedes query. It never returns another order's items in the selected detail. UI eligibility is advisory: every mutation rechecks authoritative current state.

All commands use the owner-only command wrapper; core consequential commands additionally enforce domain Actor role and transaction/idempotency rules. Contextual controls carry UUIDs internally and retain the same key across ambiguous retries. Invalid/stale state returns a clear conflict; user refreshes before retrying changed intent.

Illustrative owner money payload: `{ "action":"admin.command", "command":"product.save", "price_minor":185050 }` represents BDT1,850.50, not BDT185,050. Provider endpoints/payloads are not invented by this API.

## Guest credentials and external services

A random256-bit `shop` cookie is HttpOnly/SameSite=Lax/Secure in production and hashed at rest. Checkout creates a30-day order grant for that session; browser closure retains it. Recovery matches the saved order email then requires a ten-minute one-use challenge, at most three starts/order/hour and five code attempts. Current delivery is an owner-only development sink; production recovery/password-reset delivery remains unavailable until a real adapter is approved. An expired shopping credential can be explicitly restarted without transferring proof. Support investigation cannot authorize merely from phone/contact knowledge.

Provider-independent payment processing verifies transaction association, amount, currency, provider and reference before funding; events are deduplicated and later failure/pending cannot downgrade succeeded or late-reconciled funding. Redirects/screenshots never prove payment. Real provider authentication/signature/verification/refund/settlement behavior is unverified; commercial checkout and simulations are separately gated. COD refunds use verified cash collection and separate payout evidence, not a gateway reversal assumption. Manual courier booking/tracking is the implemented shipping boundary.

## PostgreSQL-host integration boundary — 2026-11-14

Changing the database host does not add a public API. `/api/store`, owner exports and Better Auth routes remain the only application interfaces; their owner/MFA, customer/grant and server-recalculation checks are unchanged. No browser Supabase SDK/SSR helpers, managed-auth session or `auth.uid()` policy is used. Supabase's HTTP `localhost:8000` is not a PostgreSQL connection string. Private commerce/auth objects must be absent from exposed API schemas and denied to `anon`, `authenticated` and `service_role`; actual HTTP denial is pending the intended target.

`GET /api/health` now checks the effective configured schema/USAGE, returning the existing degraded503 on failure without exposing database identity/secrets. The CLI read-only `scripts/db-preflight.ts` reports sanitized actual database/version/role/schema/extension metadata; it is not an HTTP endpoint and does not migrate or prove a data switch. Provider contracts and local adapter gates remain unchanged.

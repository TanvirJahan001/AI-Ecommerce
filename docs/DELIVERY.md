# Verification, Release, and Operations

**Purpose:** authoritative test evidence, release readiness and operational recovery. **Status:** locally verified implementation/refinement; provider sandbox and commercial gates open. **Updated:** 2026-11-14. **Related:** [PRD](PRD.md) · [DATA](DATA.md) · [API](API.md) · [SECURITY](SECURITY.md) · [Architecture](Architecture.md) · [Design](Design.md) · [Phases](Phases.md) · [Memory](Memory.md).

## Verification method and actual scope

Use pure-rule tests for exact money; isolated real PostgreSQL schemas for constraints/concurrency/transactions; Chromium browser flows against the local persistent app for owner/customer behavior; manual image inspection for readability. Test data is fictional and local adapters never move money/send external messages. Current owner/MFA and existing business data are not reset. Browser fixture receipts affect only explicitly fictional seeded SKUs; new workflow cases use uniquely named fictional products/orders.

Commands executed for refinement: `npm run db:migrate` (additive013), `npm run format:check`, `npm run lint`, `npm run typecheck`, `npm test`, `TEST_DATABASE_URL=postgresql://store:local-development-only@127.0.0.1:55432/mobile_store npm run test:db`, `npm run test:e2e`, `npm run build -- --webpack`. Focused browser runs used filenames plus unique `/tmp` output directories. `node --env-file=.env.local --import tsx scripts/capture-refinement.ts before|after` captured actual rendered baseline/current screens. README documents setup/runtime and all commands.

The earlier baseline had 2 unit, 19 PostgreSQL and 7 browser tests. Current refinement has 12 unit and 24 real-PostgreSQL tests; 18 browser scenarios passed; they are enumerated below and recorded in Memory/run record. A consolidated browser run found the delivery fee still had native integer-only step validation; it was corrected to exact BDT text input, the scenario reran successfully, and the full suite was rerun. Generated Playwright report bundles are excluded from source lint; no app failures are hidden by that exclusion.

## Release and operational gates

Local implementation dependencies: supported runtime, lockfile, PostgreSQL, migrations/fixtures, protected owner and local adapters. Sandbox dependencies: selected official provider docs/authorized credentials and actual authentication/verification/refund/event proof. Commercial dependencies: merchant approval, policy/contact/branding/language decisions, rates/coverage/battery acceptance, tax/invoice review, real transactional/reset/recovery channel, production hosting/TLS/secrets, backups/monitoring/support ownership and release approval. Future staff roster is not an owner-only prerequisite.

Dev/test/prod data/credentials must be isolated; no production PII in fixtures. Production disables local payment/recovery transport and commercial checkout. COD tests are conditional only when COD is genuinely disabled; current fixtures enable and test it. Fixed discounts are implemented; percentages remain unmet P1 and cannot be entered as if supported.

Deployment (not performed): reviewed build/migrations, backup checkpoint, staged auth/commerce smoke, monitored release; roll back compatible code/config and forward-fix schemas or explicitly reconcile restored data. Do not blindly replay payments during rollback. Backups need encryption, access control, schedule/retention/off-machine storage and restore drills; RPO/RTO require owner decisions. Proposed performance targets remain LCPp75≤2.5s and APIp95≤500ms excluding provider on agreed profiles, not measured production SLOs.

Operational exceptions: reconcile payment discrepancy before fulfillment; unknown/failed refund stays in finance queue with evidence; notification retry then manual followup; courier-update failure uses manual tracking/contact; failed COD delivery/RTO needs actual receipt/inspection; missing remittance remains receivable; stock discrepancy freezes/reconciles affected SKU with reasoned movement. Owner currently owns these tasks; future staff permissions require implementation and verification.

Remaining product/security requirements include percentage discounts, date-filtered reports/estimated margin completeness, PII masking/consent controls and any per-action step-up policy if retained by owner, native uploads if later authorized, production rate/monitoring/incident operations and full accessibility/performance review. These are not silently completed by local tests. No live-provider transactions, external messages, production deployment or commercial launch occurred.

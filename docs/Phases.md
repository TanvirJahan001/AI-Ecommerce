Implementation order remains schema/invariants → domain commands → authorized interfaces → customer/owner controls → focused DB/browser checks → documentation/evidence. Current refinement follows that order and does not depend on real merchant credentials.

Local prerequisites: maintained runtime/dependencies, isolated PostgreSQL, migrations/fictional fixtures and protected owner account. Sandbox prerequisites: selected provider official docs/access and actual authentication/verification/refund/event proofs. Commercial prerequisites: approved policies/contact/branding/language, source verification, delivery rates/coverage/restrictions, tax/invoice review, merchant approval/real adapters, transactional/recovery channel, production infrastructure/backups/monitoring/release ownership. An owner-only launch has no future staff-roster dependency.

Phase 2 is the earliest commercial-capable workflow boundary, but passing local tests does not clear sandbox/commercial gates. Returns, refunds, permissions, payment verification and recovery cannot be deferred past commercial operation. Manual courier remains accepted scope. COD checks are conditional only if genuinely disabled; current local fixtures enable COD and exercise it. Fixed discounts now exist; disabled/unsupported codes are rejected, never silently accepted. Essential order communication belongs in Phase 2; template editing is implemented Phase 3, real delivery remains external.

The current authorized next work is the database-host task below; selected real adapters and commercial gates remain separate subsequent work in DELIVERY. Native upload/storage is explicitly outside this task; staff permissions and percentage discounts remain clearly identified future/unmet work, not silently completed. The obsolete first-schema task and alternative stack proposals are superseded history in Git/Memory.
